# Peter Fintl — Executive Media Hub

A polished executive media hub hosted on **GitHub Pages** at `https://fintlp.github.io/latest-news/`. Driven entirely by static JSON files with no build step. Sections include curated media commentary, video highlights, publications, speaking engagements, a LinkedIn Posts wall, and an auto-updated news feed.

## LinkedIn Posts section

### Overview

`data/linkedin-posts.json` contains 582 posts exported from **niomaker** (a LinkedIn data export tool). The file is generated by `scripts/parse-linkedin-csv.js` from a CSV export and then enriched by four download scripts. All media is stored locally to avoid LinkedIn CDN token expiry (tokens expire every ~6 weeks).

### Post data shape

```json
{
  "id": "7297880097703759872",
  "permalink": "https://www.linkedin.com/posts/...",
  "title": "First line of the post (≤120 chars)",
  "text": "Full post text",
  "topics": ["China & EV", "ADAS & Autonomous"],
  "imageUrl": "assets/linkedin-images/7297880097703759872-0.jpg",
  "imageUrls": ["assets/linkedin-images/7297880097703759872-0.jpg"],
  "videoUrl": "assets/linkedin-videos/7297880097703759872.mp4",
  "documentUrl": "assets/linkedin-docs/7297880097703759872.pdf",
  "documentThumb": "assets/linkedin-docs/7297880097703759872-thumb.jpg",
  "articleUrl": "https://handelsblatt.com/...",
  "likes": 142,
  "comments": 18,
  "shares": 4,
  "engagement": 232,
  "publishDate": "3mo",
  "publishDateISO": "2026-04-26",
  "publishPrecision": "month",
  "source": "LinkedIn",
  "author": "Peter Fintl"
}
```

**Dates.** The CSV only carries LinkedIn's *relative* strings — `"5d"`, `"3mo"`,
`"4yr"` — which were true when the export was taken, not when the page is viewed.
`derivePublishDate()` in `parse-linkedin-csv.js` resolves them once against the
**CSV file's mtime** (not `Date.now()`, so re-running the parser is deterministic)
and stores:

| Field | Meaning |
|---|---|
| `publishDateISO` | Anchored `YYYY-MM-DD` |
| `publishPrecision` | `day` \| `month` \| `year` — how much of that date is actually known |

Precision matters because the source is not uniformly precise: `"5d"` pins a day,
`"3w"` only pins a month, `"4yr"` only pins a year. Card and modal renderers show
no more precision than this field allows — a `"4yr"` post renders as `2022`, never
as a specific day. Current spread: 500 year, 90 month, 3 day.

`mergeResolvedDates()` preserves an existing `publishDateISO` across re-parses:
a post exported today as `"3mo"` reads `"1yr"` in next year's export, and the
earlier, finer reading is the one worth keeping.

Both `app.js` (`liDateParts`/`liDateHtml`) and `scripts/prerender.js` (`liDateHtml`)
format these — **the two must stay in sync**, as with the rest of the LinkedIn card
markup. Posts with no `publishDateISO` fall back to the raw relative string.

**`imageUrl` priority** (what ends up as the card image):

| Source | Condition |
|---|---|
| `assets/linkedin-images/` | Post had its own attached photo |
| `assets/linkedin-videos/{id}-thumb.jpg` | Video post, no other image |
| `assets/linkedin-docs/{id}-thumb.jpg` | PDF post, no other image |
| `assets/linkedin-articles/{id}-article.*` | Article-promotion post (no LinkedIn photo) |
| `null` | Text-only post → LinkedIn-branded placeholder shown |

**Current counts:**
- 417 posts → `linkedin-images`
- 30 posts → `linkedin-videos` thumbnail
- 6 posts → `linkedin-docs` thumbnail
- 41 posts → `linkedin-articles` OG image
- 88 posts → no image (text-only placeholder)
- 271 posts have `articleUrl` (the "Read Article" button appears in the modal)
- 30 posts have `videoUrl` (local MP4 via LFS)
- 6 posts have `documentUrl` (local PDF with download button)

### Updating LinkedIn posts (re-export flow)

Run these steps whenever you export a new CSV from niomaker:

```bash
# 1. Place the new CSV in the repo root as LI_POSTS_fintlp_568.csv
#    (overwrite the old file)

# 2. Regenerate JSON (idempotent — preserves all local asset paths)
node scripts/parse-linkedin-csv.js

# 3. Download any new images (skips already-downloaded)
node scripts/download-linkedin-images.js

# 4. Download any new PDFs + thumbnails
node scripts/download-linkedin-docs.js

# 5. Fetch OG images for new article-promotion posts
node scripts/download-linkedin-article-images.js

# 6. Download any new videos (requires Git LFS + ffmpeg)
node scripts/download-linkedin-videos.js

# 7. Optionally resolve lnkd.in shortlinks to real article URLs
node scripts/resolve-article-urls.js
```

All scripts are **idempotent** — already-processed posts are skipped. Run them in order after a re-export.

**Prerequisites for step 6:**
```bash
brew install git-lfs ffmpeg
git lfs install
```

### Why local assets?

LinkedIn CDN URLs contain a signed expiry token (`?e=<unix_timestamp>`). Tokens typically expire every 6 weeks. After expiry all post images return 403. By downloading all media locally and pointing `imageUrl` to `assets/linkedin-*`, the site never needs CDN token renewal.

### parse-linkedin-csv.js — merge functions

The parser calls four merge functions in sequence after building posts from the CSV. These preserve local asset paths across re-exports:

| Function | Reads from | Sets |
|---|---|---|
| `mergeLocalImages()` | `assets/linkedin-images/{id}-{n}.{ext}` | `imageUrl`, `imageUrls` |
| `mergeLocalDocs()` | `assets/linkedin-docs/{id}.pdf` + `{id}-thumb.*` | `documentUrl`, `documentThumb`, `imageUrl` |
| `mergeLocalArticleImages()` | `assets/linkedin-articles/{id}-article.*` + existing JSON for `articleUrl` | `articleUrl`, `imageUrl` (only if no other image) |
| `mergeLocalVideos()` | `assets/linkedin-videos/{id}.mp4` + `{id}-thumb.*` | `videoUrl`, `imageUrl` (only if no other image) |

`mergeLocalArticleImages` also reads the existing `data/linkedin-posts.json` to re-apply any `articleUrl` values from the previous run (including manually set ones).

### Video hosting — local vs. production

GitHub Pages does **not** serve Git LFS files (it delivers the 134-byte pointer instead of the binary). Videos are therefore handled differently by environment:

- **localhost / 127.0.0.1**: inline `<video>` player with the local MP4
- **Production** (`fintlp.github.io`): thumbnail image + "Watch on LinkedIn →" overlay link to the post permalink

Detection in `app.js`:
```js
const isLocal = location.hostname === 'localhost' || location.hostname === '127.0.0.1';
```

### articleUrl and the "Read Article" button

When a post references an external article, `articleUrl` stores the link and a "📰 Read Article" button appears in the post modal. 271 posts currently have `articleUrl`. Many are `lnkd.in` shortlinks — these work correctly in a browser (they redirect to the article) even though they cannot be resolved server-side (lnkd.in returns HTTP 200 with JavaScript redirect, not a 3xx).

To attempt re-resolution of shortlinks:
```bash
node scripts/resolve-article-urls.js
```

### UI behaviour

The post cards show:
- **Photo posts**: the image with no badge
- **PDF posts**: the PDF thumbnail with a `📄 PDF` badge (top-right corner)
- **Video posts**: the video thumbnail with a `▶` play badge (bottom-right corner)
- **Article-promo posts**: the article OG image
- **Text-only posts**: LinkedIn blue gradient placeholder with a subtle "in" watermark

Clicking a card opens a modal with the full text, engagement stats, and action buttons:
- "📰 Read Article" — visible only when `articleUrl` is set
- "📄 Download PDF" — visible only when `documentUrl` is set
- "View on LinkedIn →" — always visible

Both the article and PDF buttons use `style.display` (not the `hidden` attribute) because CSS `.btn { display: … }` rules can override the `hidden` attribute.

## News feed

### How it works

1. **GitHub Actions** runs `scripts/fetch-news.js` daily at 09:11 Vienna time.
2. The script queries **Google News RSS** (13 locales) for `"Peter Fintl"` and optionally **Brave Search** for topic queries.
3. Results are normalised, deduped, and merged into `data/archive.json` (rolling 1-year window).
4. On page load, `app.js` fetches `data/archive.json` and renders the **Latest Coverage** section.

### Data sources

| Source | What it covers |
|---|---|
| Google News RSS — 13 locales | en-US, en-GB, en-AU, de-AT, de-DE, de-CH, zh-TW, zh-CN, ja, ko, fr-FR, it-IT, nl-NL |
| Brave Search News API | Optional topic queries; requires `BRAVE_API_KEY` secret |

### Image pipeline

Each news card tries the following in order:

| Priority | Source |
|---|---|
| 1 | `og:image` / `twitter:image` scraped from article page |
| 2 | RSS `<media:content>` / `<media:thumbnail>` / `<enclosure>` |
| 3 | Outlet logo matched via `data/as-seen-in.json` (supports `aliases`) |
| 4 | `EXTRA_SOURCE_DOMAINS` map in `fetch-news.js` |
| 5 | Domain extracted from source name |
| 6 | `google.com/s2/favicons?domain={host}&sz=256` (always resolves) |

Cards whose `imageUrl` is a favicon URL get `object-fit: contain` with padding in CSS.

### Adding articles manually

Add an entry to `data/manual-overrides.json`:

```json
{
  "title": "Article title",
  "url": "https://www.outlet.com/article-path",
  "source": "Outlet Name",
  "sourceUrl": "https://www.outlet.com",
  "faviconUrl": "https://www.google.com/s2/favicons?domain=outlet.com&sz=128",
  "imageUrl": null,
  "publishedAt": "2026-04-29T00:00:00.000Z",
  "snippet": "Short description.",
  "manually_added": true
}
```

Then rebuild locally:
```bash
node scripts/fetch-news.js
git add data/manual-overrides.json data/archive.json data/news.json
git commit -m "feat: add article to manual-overrides"
git push
```

**Important:** Use plain ASCII double quotes only. Typographic quotes (`"` `"` `„`) silently break JSON parsing.

### Adding outlet logos

Add an entry to `data/as-seen-in.json`:
```json
{
  "name": "Outlet Name",
  "aliases": ["shortname", "shortname.com"],
  "url": "https://www.outlet.com/"
}
```

For frequent outlets not in `as-seen-in.json`, add them to `EXTRA_SOURCE_DOMAINS` in `scripts/fetch-news.js`:
```js
const EXTRA_SOURCE_DOMAINS = {
  'tablebriefings': 'table.media',
  // normalizeSourceKey(sourceName) → domain
};
```

## Pre-rendering (SEO)

`scripts/prerender.js` injects rendered HTML into `index.html` so crawlers that don't execute JavaScript (Bingbot, most social and LLM crawlers) can read the content. `app.js` overwrites the same containers at runtime, so behaviour for real users is unchanged.

**This is not optional.** It runs in CI on every news fetch and on any push touching a data file it reads. Committing a data change without re-running it leaves `index.html` stale.

### What gets pre-rendered

| Target | Source | Notes |
|---|---|---|
| Hero, pillars, bio, contact, footer | `data/site.json` | |
| As seen in | `data/as-seen-in.json` | |
| Media, publications, speaking, library | respective JSON files | |
| LinkedIn posts → `#li-grid` | `data/linkedin-posts.json` | first 12, newest first |
| Latest coverage → `#news-results` | `data/archive.json` | first 12, 90-day window |
| `VideoObject` JSON-LD → `#video-schema` | `data/videos.json` | embedded videos only |

Video *thumbnails* in `#videos` are still built client-side.

### The invariant that matters

Each card renderer mirrors its `app.js` counterpart **at that section's default state** — same filter, same sort order, same `pageSize`. `app.js` replaces these containers on hydration, so if the static markup disagreed the user would see cards visibly reshuffle on load.

These must stay in sync across the two files:

| `prerender.js` | `app.js` |
|---|---|
| `NEWS_PAGE_SIZE` | `NEWS_STATE.pageSize` |
| `LI_PAGE_SIZE` | `LI_STATE.pageSize` |
| `BLOCKED_HOSTS` | `FRONTEND_BLOCKED_HOSTS` |
| `TOPIC_COLOURS` | `TOPIC_COLOURS` |
| `cleanText()`, `parseRange()`, `liRelativeDays()` | same names |

The LinkedIn default is **"Most Recent"** — `LI_STATE.sort = 'date'` in `app.js`, the first `#li-sort` option, and the sort used by `renderLiCards()`. Changing the default means changing all three.

Note that `publishDate` in the CSV export is a coarse relative string (`"1yr"`, `"3mo"`), so posts of the same stated age share a bucket — up to ~90 of them — and are not ordered within it. The newest posts surface correctly at the top, which is what the sort is for; deeper down, same-age ordering is arbitrary.

After changing either file, verify the static and hydrated card order still agree — serve the site locally, read the card titles out of `index.html` on disk, and compare against `document.querySelectorAll('#news-results .news-card__title')` after load. Decode HTML entities before comparing, or `&quot;` will produce false mismatches.

### VideoObject schema

Only videos with an `embed` URL are marked up. A thumbnail that links out to another platform is not a video on this page, and claiming otherwise is a structured-data mismatch that risks a manual action.

Entries missing any Google-required field (`name`, `description`, `thumbnailUrl`, `uploadDate`) are skipped rather than emitted as invalid markup — so an incomplete `videos.json` entry degrades gracefully instead of breaking the whole block.

Missing durations and thumbnails can be recovered from Vimeo's oEmbed API. Unlisted videos need their hash token, which lives in the `embed` URL:

```bash
# https://player.vimeo.com/video/1133726114?h=ed83b8fc69
curl -s "https://vimeo.com/api/oembed.json?url=https%3A%2F%2Fvimeo.com%2F1133726114%2Fed83b8fc69"
```

Swap the `-d_295x166` suffix on a returned thumbnail for `-d_1280` to get the full-size version. Validate the result with Google's [Rich Results Test](https://search.google.com/test/rich-results).

| Trigger | Workflow |
|---|---|
| Daily news fetch | `.github/workflows/fetch-news.yml` |
| Push touching a pre-rendered data file | `.github/workflows/prerender.yml` |
| Manually | `npm run prerender` |

## Indexing (sitemap, robots, Search Console)

Pre-rendering makes the page *readable* to crawlers. This section covers getting it *found*.

The canonical URL is the trailing-slash form, `https://fintlp.github.io/latest-news/`. The bare `/latest-news` 301s to it — that redirect is GitHub's, not ours, and there is nothing to fix when it shows up in reports.

### `robots.txt` in this repo does nothing

Google reads `robots.txt` **only from the domain root**. This repo's copy is served at `https://fintlp.github.io/latest-news/robots.txt`, which is never fetched. The file that actually governs crawling lives in a **different repository** — `fintlp.github.io`, the user-page repo that serves the domain root.

That repo also serves the root landing page, which deliberately carries `<meta name="robots" content="noindex, follow">`.

The two `robots.txt` files are currently identical, which is exactly what makes this dangerous: editing the one in this repo looks like it works and changes nothing. **Crawl-directive changes belong in the `fintlp.github.io` repo.**

```bash
# what Google actually reads
curl -s https://fintlp.github.io/robots.txt
```

### Sitemap

`sitemap.xml` holds the single canonical URL and is regenerated by `scripts/fetch-news.js` on the daily cron, so `<lastmod>` stays current without manual work. The root `robots.txt` points at it.

**Do not submit or resubmit a sitemap right after pushing.** GitHub Pages serves 404s briefly while a deploy is in flight, and a submission that lands in that window is recorded as *"Sitemap could not be read"* — a failure that persists in the UI until Google happens to retry. Three submissions made during a six-commit deploy burst on 2026-07-26 all failed this way against a file that was valid the whole time. Wait for the deploy to finish, confirm, then submit:

```bash
curl -sI https://fintlp.github.io/latest-news/sitemap.xml
```

### Search Console has two properties

| Property | Use |
|---|---|
| `https://fintlp.github.io/` | domain-wide; **aggregates are misleading** |
| `https://fintlp.github.io/latest-news/` | the real site |

The root property reports the noindex landing page and the bare `/latest-news` redirect as "not indexed". Both are expected, and together they make the Pages report read "0 indexed pages" while the site is in fact indexed and ranking.

**Trust URL Inspection on the canonical URL, not the Pages report** — it is live and per-URL, where the aggregate reports lag by days and a newly verified property shows "processing data" for its first day or so.

## Accessibility

### Minimum tap targets

`.li-card-link`, `.li-card-expand`, `.lib-card-expand` and `.news-external-link` are inline text controls that render 16–21px tall — under the 24px WCAG 2.2 AA minimum (2.5.8). One shared rule in `styles.css` grows their **hit area** with a transparent `::after` overlay instead of padding, because padding would push the surrounding card layout around. The overlay is vertical-only so it can never reach a sibling control (e.g. `.li-card-link` must not overlap `.li-card-stats`).

Each base selector needs `position: relative` for the overlay to anchor. If you add another small inline control, add it to that rule rather than copying the block.

To verify, hit-test a few pixels outside the visual box:

```js
document.documentElement.style.scrollBehavior = 'auto';   // else coords go stale
const e = document.querySelector('.li-card-expand');
e.scrollIntoView({block:'center', behavior:'instant'});
const r = e.getBoundingClientRect();
// should HIT at ±11 (22px span) despite a 16px visual box
document.elementFromPoint(r.left + r.width/2, r.top + r.height/2 - 11);
```

### Other requirements

- **Topic filter buttons** carry `aria-pressed`, set via `liSetActiveTopic()` in `app.js`. The `.active` class conveys selection visually only — keep both in sync.
- **Every control needs an accessible name.** This codebase uses `aria-label` (there are no visible `<label>` elements): `#li-sort` "Sort posts", `#li-search` "Search posts", `#timeRange` "Time window", and so on. A `placeholder` is **not** a substitute.
- **Skip link** is the first focusable element, targeting `<main id="main-content" tabindex="-1">`. The `tabindex="-1"` matters — without it some browsers scroll but never move focus.

### Deliberately not changed

Two things an automated audit flags that are actually correct. Measure before "fixing" either:

| Apparent issue | Why it's left alone |
|---|---|
| 37 images with `alt=""` | Correct as-is. News thumbnails and favicons sit inside a link whose text already names the article and source, so descriptive `alt` would duplicate the link text; LinkedIn post images sit directly beside the post text. Empty `alt` is the right call for redundant/decorative images — filling these in would make screen-reader output noisier, not better. |
| ~49 images with no `width`/`height` | No layout shift happens. The containers declare `aspect-ratio: 16 / 9` with the image absolutely positioned inside, which reserves the space before load, and favicons/logos are fixed-size in CSS. **Measured CLS is 0.** |

## Local preview

```bash
npx serve .
# or: python3 -m http.server 3000
```

Open `http://localhost:3000`. The LinkedIn video player works locally (inline `<video>`); on production it shows a thumbnail + "Watch on LinkedIn" link instead.

### Stale `styles.css` / `app.js` while testing

`python3 -m http.server` sends no `Cache-Control`, so browsers apply heuristic caching to the sub-resources. Editing `styles.css` or `app.js` and reloading can keep serving the **old** file — a hard reload doesn't always clear it either. Working changes then look broken: computed styles show the previous values and new event handlers never run.

Confirm what the server is actually sending before debugging the code:

```bash
curl -s http://localhost:3000/styles.css | grep 'your-new-rule'
```

If the server has the change but the page doesn't, it's the cache. Either restart the server on a **different port** (a new origin gets a clean cache — the reliable fix), or re-inject the stylesheet from the console:

```js
const old = document.querySelector('link[href*="styles.css"]');
const link = document.createElement('link');
link.rel = 'stylesheet'; link.href = 'styles.css?bust=' + Date.now();
document.head.appendChild(link); old?.remove();
```

Two related gotchas when verifying interactively:

- `html { scroll-behavior: smooth }` is set, so `scrollIntoView()` animates and any `getBoundingClientRect()` read straight afterwards is stale — `elementFromPoint()` then misses. Set `document.documentElement.style.scrollBehavior = 'auto'` first.
- Programmatic `.focus()` does **not** trigger `:focus-visible`, and an unfocused window doesn't match `:focus` at all even when `document.activeElement` is set. Focus styling has to be checked with a real keypress, not a script.
